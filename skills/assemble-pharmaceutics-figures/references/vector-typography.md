# 矢量识别与统一字号

在尺寸与信息密度评估后、最终组图批准前执行。先识别，再判断是否需要调整；已经一致则不生成无意义副本。字号以最终放置尺寸为准，不以打开源文件时的视觉大小为准。

## 从既有组图参考提炼的层级

面板字母明显大于坐标、刻度和图例；相同类型文字应一致，标题可略大。截图只能推断相对层级，不能精确读出原稿 pt。以下为可修改的工作默认值，不是截图测量结果或期刊标准：

|角色|最终字号|处理|
|---|---|---|
|panel：A/B/C 等|12 pt|沿用已确定的面板标注默认值|
|title：面板内部标题|10 pt|保留标题与正文层级|
|body：轴标题、刻度、图例等普通文字|8 pt|同一角色统一；默认容差0.25 pt|
|keep：公式或明确保留的例外|原样|在报告中列出，不能称为全图已统一|

不把所有文本强制压成一个字号。明确的期刊要求或用户确认值优先，写入 profile JSON。字体家族、粗斜体、颜色、文字内容、曲线和数据均保留；本功能只改字号及与其关联的基线偏移。

## CLI

Windows 实际执行需要 Illustrator 和 `pip install '.[windows]'`；PDF还需要 `pip install '.[vector]'` 以核验单页。可先不加 `--run-illustrator` 生成 JSX，但这只表示脚本待运行，不能声称已检测或已修改。

```powershell
pharmfig fonts-inspect source.svg --output runs/font-inspection --final-width-mm 80 --run-illustrator
pharmfig fonts-normalize runs/font-inspection/font-audit.json --output runs/font-normalized --final-width-mm 80 --roles roles.json --profile profile.json --run-illustrator
```

`--final-width-mm` 指**整个源画板**在最终成品上的放置宽度。若组图按可见裁切框定位，完整画板宽度 = 最终有效内容宽度 ÷ 已批准的横向内容比例。例如有效宽60 mm、内容宽占80%，传入75 mm。画板含边距时直接传60会错误换算字号。布局尺寸改变后必须重新评估。

`profile.json` 例：`{"body":8,"title":10,"panel":12}`。`roles.json` 例：`{"0":"panel","3":"title","8":"keep"}`。ID来自**当前检查报告**，不要跨文件复制；仓库的示例角色表只对应合成示例在本次Illustrator导入中的顺序，使用前核对。

## 识别和判断边界

- Pillow按内容识别可解码位图，扩展名伪装成SVG也不认作矢量。AI/PDF/SVG/EPS由Illustrator实际打开并统计路径、可编辑文字、位图和链接对象；扩展名本身不是证据。
- `editable_vector`：存在可编辑文字，未发现位图或链接；仍不能证明所有路径都不是转曲文字。
- `mixed`：可编辑文字与位图／链接混合。只处理可编辑部分，不能保证位图或链接内部字体一致。
- `vector_without_editable_text`：有路径但无文字对象，可能是转曲文字或无字图；不自动OCR或重造文字。
- 栅格、无可编辑文字、多个画板或角色不明时，报告人工复核，不虚构“已统一”。仅支持单页PDF，避免静默处理第一页。
- 默认从普通文字框的基准字号估计正文；单个大写字母和显著偏大／偏小文字需要角色表。此推断不是语义识别，使用前审阅每个文字框。
- 同框混合字号／上下标按同一个比例缩放，保留相对字号与基线偏移。导入后拆成多个框的公式须作为一组人工核对；无法可靠关联时使用keep，不把上标当普通刻度放大。

## 输出与验收

检查输出 `font-audit.json`（实际对象）、`font-report.json`（角色、源字号、最终字号、是否需调整）。调整输出 `font-plan.json`、新 `normalized.ai` / `normalized.pdf` 和 `font-after.json`；源文件不保存、不覆盖，已有输出拒绝覆盖。审阅报告包含源SHA-256；源改变需重做检测。运行前关闭源文档，避免操作用户正在编辑的窗口；脚本只关闭自己打开的文档。

调整后核验文字内容、每字符字号和基线偏移；检测新增文字框相交及超画板位置。**必须渲染PDF核查**长标签、图例、轴标题、公式、比例尺、缺字、字体替代、区域文字溢出及与非文本对象碰撞。程序只检查文字框之间的新增碰撞，不能保证所有图文无碰撞；始终输出“需要视觉审阅”，不能等同正式期刊合规。

若字号增大导致拥挤，优先扩大面板或调整行列，不反向把字体缩回不可读尺寸。审核后将新副本作为来源，重新检查有效边界及布局；既有源哈希／批准约束仍有效。CLI不会静默替换manifest来源，也不会因生成副本自动批准整幅Figure。

科研素材、审阅报告和原图不提交GitHub。仓库仅存合成示例、实现和通用规则。
